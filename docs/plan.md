# 고정 역할 정책 및 P1 보완 계획

2026-09-14. 사용자 승인: 직전 대화의 역할별 권장안대로 구현 시작.
운영 데이터 접근, 배포, 병합은 승인 범위에 포함하지 않는다.

## 요구 및 작업 순서

1. 고정 역할 정책: 입력자·담당자·팀장·센터장과 시스템 관리자 자격을 분리한다.
2. 권한표 편집·저장 경로를 제거하고 읽기 전용 역할 안내를 제공한다.
3. 역할뿐 아니라 담당 범위·작성자·보고서 상태를 서버에서 검사한다.
4. 역할/담당 변경, 대행, 위험 작업 승인·취소 이력을 보존한다.
5. 기반 검증 후 P1을 순서대로 보완한다: 직원 계정 보호, 범위 제한,
   마감 경합, 권한 갱신 일관성, 영수증 계좌 소속, 정리 경합,
   연초 잔액, 보고서 의견, UID 재사용.

## 정책

- 입력자: 담당 범위에서 본인 미제출 거래 입력·수정·취소·증빙 추가.
- 담당자: 담당 범위 장부 관리·보고서 제출, 제출 이후 반려/회수 후 수정.
- 팀장: 담당 팀 검토·결재, 금융 원본 직접 수정 대신 반려.
- 센터장: 전체 검토·최종 결재·확정 취소. 일반 금융 입력을 자동 상속하지 않는다.
- 시스템 관리자: 기술 운영 자격. 업무 역할의 최종 결재·전체 금융 조회를 자동 부여하지 않는다.
- 작성자 자기 결재, 마감 직접 우회, 물리적 거래 삭제, 일반 화면 초기화 금지.
- 과거 권한표와 오래된 caps가 새 정책을 확장하지 못한다.
- 대행은 기간·대상·사유가 있는 명시적 지정으로만 허용한다.

## 확정된 세부 결정 (2026-09-15 재개)

- 팀장의 담당 범위는 직원의 팀 이름이 아니라 `clients.teamLeader`에 지정된 UID 기준이다.
- 역할 변경·관리자 지정의 승인자와 실행자는 서로 달라야 한다. 다른 승인자가 없으면 보류한다.
- 권한 안내는 입력자와 모바일에서도 접근할 수 있어야 한다. 안내 접근이 다른 설정 변경 권한을 부여하지 않는다.
- 업무 역할이 없는 시스템 관리자 계정은 유효한 기술 전용 계정으로 표시한다.

## 검증 기준

역할별 허용/거부, 관리자 비상속, 오래된 정책 무효, 미배정 접근 거부,
자기 결재 거부, 마감·파일 동시 실행, 연초 잔액을 회귀 테스트한다.
기존 테스트 실패는 의도된 정책 변경과 결함으로 구분한다.
미완료 작업은 완료로 표시하지 않고 배포를 막는다.

## 기술 구성

기존 Vanilla JS, Firebase Functions, Firestore/Storage Rules를 유지한다.
새 외부 서비스 및 비용 발생 기능을 추가하지 않는다.
